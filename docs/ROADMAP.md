# 開發路線圖

## 擷取器終態與下一階段

**本輪擷取器開發／研究已結案，沒有待自動續跑的矩陣或長測。** 五路徑選型、預設不存圖政策及 gRPC Windows 接收區塊正式化均已完成。主用為 gRPC payload fast／256 KiB；正式備用暫缺，WGC 僅為候選。DXGI 留作受限比較，scrcpy 本次軟體 H.264 配置不列主／備，MMAP 僅診斷。終態主紀錄見 [最後驗收](CAPTURE_FINAL_ACCEPTANCE_20260926.md)。

現行 gRPC overlay revision 2 的 Release 34／34 回歸、18 批短測及正式擷取／恢復／observe 驗證均完成，詳見 [接入紀錄](GRPC_TRANSPORT_INTEGRATION_20260926.md)。這些證據不代表 p99、絕對來源年齡、長期性能或遊戲時序已通過。

下一階段 M3 按以下順序推進；本次結案不自動啟動這些工作：

1. 把 bench 已測的 gRPC 相對積壓保護接入 Session/profile，記錄實際配置並補針對性回歸。
2. 接通 epoch／幾何／證據期限與失效撤銷，核對畫面到觸控座標。
3. 先對簡單目標完成 pixels→預測→排程→觸控→畫面回饋的實機時序驗證，再評估 Phigros 辨識與 assist。

若未來需要正式備用，另以 WGC 跟隨損失定位、Session／座標接線及關鍵失效驗證取得資格。目前主用失效應明確停止，不自動切換未驗證候選。

## 五路徑開發與縮短測試歷史

以下保留選型覆核前的計畫與「初步」用語；現行終態以上節及最後驗收文件為準，不能據此重新啟動已取消的工作。

2026-09-26 最新使用者修訂取消剩餘完整矩陣與長測，以現有 r4 的 37 個有效正常批次、3 個失敗及必要恢復／120 秒補測作初步選型。原 96 批仍未完成；本版長期穩定性、完整負載／driver fault 未驗證。主用／備用和明確限制見 [比較報告](CAPTURE_COMPARISON_20260926.md)，性能數值門檻維持 null／待決。M3 簡單目標實機閉環仍為下一階段。

2026-09-26 使用者已授權依 [五路徑集中比較計畫](CAPTURE_FIVE_BACKENDS_PLAN_20260926.md) 在 main 工作目錄完成 gRPC payload 優化、WGC、DXGI、scrcpy、MMAP 診斷收尾，再以同一凍結版本集中測試。正常來源研究範圍更新為 **40–59 Hz**；舊段落中的 40–57 Hz 為歷史決策及當時 Fixture 場景，不作本輪上限。完成候選正確性與量測後才提出主用／備用及性能門檻建議；使用者確認前 `performance_pass` 維持 pending。M3 真實簡單目標閉環與遊戲功能仍在下一階段。

上一輪已完成來源凍結、C++20 基礎與單程序執行、既有 gRPC payload／ADB／診斷 MMAP、簡單目標與 scheduler、Android Native Fixture，以及功能與資料驗收。本輪 T6–T7 的候選狀態和待實測項目見 [就緒矩陣](CAPTURE_READINESS_20260926.md)。功能驗收仍以 C++ 命令、原始 JSONL 與 Fixture pixels 為準；舊 Python pass 不直接轉移。遷移階段逐項狀態見 [遷移矩陣](CPP_PARITY_MATRIX.md)。

T0 來源快照已逐 hash 核對並凍結於 `legacy/`；T1–T5 的 C++ 程式、新 Fixture、Release／Debug／嚴格 ASan 測試與新原始量測已完成，限制見 [驗收紀錄](CPP_ACCEPTANCE_20260925.md)。5 vCPU／8 GB C++ Release 的三批 60 秒歷史基線已取得；p95／p99、無圖空窗、來源跟隨與失敗容許的數值門檻仍待使用者決定。當時的 40–57 Hz 條件並非自動通過性能，本輪採 40–59 Hz。

## 歷史路線與驗收紀錄

> 2026-09-25 使用者重排路線：先全 C++ 遷移（含既有功能與缺陷修正），再完成 gRPC payload／WGC／DXGI／scrcpy／MMAP 五候選評估，之後才進入新的主程式閉環與遊戲功能。40–57 Hz 為正常來源範圍；5 vCPU／8 GB RAM 為下一輪 AVD 目標，實際配置須核對。新性能數值門檻由新基線後的使用者決策決定，不回溯改寫歷史結果。工作包見 [C++ 遷移計畫](CPP_MIGRATION_PLAN.md)。

> 2026-09-25 獨立驗收結論：**先修 M1 的 3 個排程問題並補 M2 軌跡證據，再驗收 M3。** 原有 70 tests 通過，額外契約重現 3/3 失敗；此前「M0–M2 實作驗收」不能視為全數通關。詳見 [驗收報告](ACCEPTANCE_20260925.md)。統一擷取重測保留所有日常負載批次及來源率，不與先前不同來源條件混算。

> 2026-09-25 M0–M2 實作驗收：observe runtime／profile／manifest、單 owner 一般接觸排程、gRPC `sendTouch`、獨立 Android 觸控 Fixture、前景防誤觸的能力工具與降頻主機預覽已落地。六類各 30 組、取消 30 組、雙指 batch 30 組皆由 Fixture 可見 pixels 驗證；四角各一次為 smoke。真實 RPC deadline 逾時嘗試未重現，fake server 逾時／未知狀態回歸與實機 channel 斷線後緊急釋放已分開驗證。遊戲 assist 維持禁用；下一階段是 M3 真實簡單目標閉環，不能由本次觸控量測直接宣稱遊戲可用。環境、分布與限制見 [量測紀錄](MEASUREMENTS.md#主程式-m0m2-觸控-fixture2026-09-25)。

> 2026-09-25 主程式開發：詳細工作包與驗收依 [主程式完整開發計畫](MAIN_PROGRAM_DEVELOPMENT_PLAN.md)。使用者選擇 CLI＋即時診斷預覽，指定 GPT-6 Sol xhigh 開發。新 runtime 以 process＋gRPC payload 為開發基線，先做 M0–M2 核心／觸控 Fixture，再驗收 M3 真實閉環，最後進入遊戲辨識。這不表示既有路線圖第 1–4 階段已全部通過，也不宣稱遊戲延遲已達標。

> 2026-09-24 驗收修正：程序版的阻塞 RPC 取消／MMAP 殘留回收、暖機 consumer skip 邊界與 CPU 取樣窗口已補離線回歸。資源 CPU 現在按各自取樣區間估計並揭露邊界偏差；舊程序 CPU 數據不視為精確正式窗口量測。MMAP 繼續限制為診斷，本次沒有新增 emulator 實測結論。

> 2026-09-24 冷開發：獨立程序 payload 路徑、固定容量 IPC 與 opt-in MMAP 診斷候選已完成離線實作及測試。實機相容性、同條件尾端延遲和來源 MMAP 一致性仍待集中驗收；不改變先完成擷取／觸控能力與簡單目標閉環、最後才做 Phigros 專用辨識的順序。清單見 [擷取低延遲開發計畫](CAPTURE_LOW_LATENCY_PLAN.md)。

> 2026-09-24 Fixture 實機續測：已驗證獨立程序 payload 可連續擷取並完成 5 秒 Session；正常 thread／process payload 各三批 60 秒，MMAP 指定 1280×720 後另做三批診斷。MMAP 預設 `0×0` 無影格，仍因上游一致性未證明而禁止 Session。這次 Fixture 可見更新率約 39–44 Hz，三配置都不能套用約 60 Hz 的 55 張／秒研究門檻，也沒有證據選定遊戲用後端。完整分布與原始資料見 [量測紀錄](MEASUREMENTS.md)。

> 2026-09-24 進度：`phigros` AVD 與遊戲已由使用者準備；第 0 階段已有 AVD／ADB 盤點。第 1 階段新增可選的 Emulator gRPC RGB888／RGBA8888 持續擷取、容量 1 緩衝區、可取消的來源與分布量測；真實 AVD 已確認連線、像素方向、Chrome 與原生動態畫面的計數，以及 500 ms 接收停頓後的短暫上游積壓。原生 1280×720 先前約 35 Hz 的條件未達研究目標；後續約 59 Hz Fixture 條件的三批正式 60 秒量測達畫面數與到達間隔門檻，條件變動原因未證實。來源絕對年齡與擷取後端選型仍未完成。第 2 階段僅有觸控契約、座標變換和假後端驗證；第 3 階段已有合成預測／排程及主機時序基線；第 4 階段已有可重現的合成 pixels-to-touch-to-pixels 測試。第 1–4 階段的**完整實際模擬器驗收尚未完成**，第 5–6 階段未開始。詳見 [量測紀錄](MEASUREMENTS.md)。

> 第二輪修正已將 gRPC 基準的就緒、暖機、正式窗口與 CPU／計數窗口分開；後續修正暖機影格污染正式 consumer skips，以及健康探測期間新影格到達卻誤報 `ERROR` 的競態。事件式 Session 逾期會撤銷新鮮度資格，來源時間不連續不再無限吞圖。先前乾淨提交的三批 35.4–35.9 Hz 結果保留；後續約 59 Hz Fixture 條件下的乾淨提交三批達研究門檻。真實 `0×0` inactive 未由可逆螢幕關閉或視窗最小化重現；客戶端斷線／重連已驗證。第 1 階段仍缺來源絕對年齡與端到端時序驗收。正式重測結果見 [量測紀錄](MEASUREMENTS.md)。

依序建立「即時畫面 → 辨識與預測 → 排程 → 觸控 → 再觀察畫面」的閉環。每階段都要留下可重現的設定、測試程序與結果，再進入下一階段。效能門檻應根據實測的遊戲判定需求與端到端誤差決定，不預先宣稱能達到特定成績。

## 使用前提與共通規則

- 使用者自行在模擬器安裝正版 Phigros，並自行登入一個已完成新手教學的全新帳號。程式不接收、保存或記錄帳號密碼與驗證碼，也不自動處理登入或教學。
- 第一版由使用者手動處理公告、權限、選單與選曲。程式從即時畫面確認進入遊玩狀態後自動接手；遇到暫停、結算或無法確認的畫面即停止遊玩觸控。
- ADB 只用於連線、能力盤點及啟動已安裝的應用。執行時的遊戲決策只能來自最新畫面；不讀譜面、遊戲內部狀態、記憶體或預錄按鍵序列。
- 每次量測記錄主機與 OS、模擬器和 Android 版本、遊戲版本、AVD 型號、CPU 架構、解析度、方向、縮放、目標幀率、擷取與觸控後端、主機負載、樣本數及測試命令或程序。只用同一個主機 monotonic clock 算時差。
- 結果至少報告 p50 / p95 / p99、最大值、掉幀或失敗數與 jitter，並說明暖機、測量點和原始日誌位置。日誌與錄影只供診斷及離線分析，不在執行時回饋成固定譜面或觸控序列。

## 0. 環境與能力盤點

- 建立可重複的 AVD 建立、啟動和連線程序；記錄 Android 版本、解析度、方向、縮放與可用幀率。若比較其他模擬器，分別保存設定與結果，不先假定產品已選定。
- 使用者完成遊戲安裝及登入，人工確認可進入選曲與遊玩畫面。程式只查驗應用已安裝及可啟動，不碰憑證或存檔。
- 盤點擷取與觸控候選路徑、權限、座標系和限制。多台裝置連線時須明確選定序號，不自動猜測。

**完成條件：** 新環境能按文件重現 AVD 與連線，遊戲可手動運行；有能力表及環境紀錄。若模擬器或登入尚未就緒，可先做合成與假後端測試，但不能宣稱模擬器整合已驗證。

## 1. 模擬器與即時畫面

- 建立可替換的 Capture 介面。每個 frame 記錄序號、尺寸、像素格式與擷取完成時間；如可取得可靠的畫面產生時間，另存欄位，不把取回時間冒充產生時間。
- 建立 Session controller：單一命令選定裝置，先啟動日誌與擷取、確認連續有效畫面，再開啟已安裝的遊戲。記錄各階段 monotonic 時間戳；啟動命令返回不等於畫面載入完成。
- 以容量為 1 的最新 frame 緩衝區供下游讀取。刻意放慢下游時，驗證舊 frame 被覆蓋而非排隊處理。
- 量測擷取間隔、frame 年齡、停頓、掉幀與 CPU 負載；以尾端延遲比較擷取後端，將選型理由補入架構文件。
- 依 [擷取實作計畫](CAPTURE_IMPLEMENTATION_PLAN.md) 先實測模擬器 gRPC 原始畫面串流；只有它不可用或不適合時才依證據評估 MMAP、Windows Graphics Capture 或 scrcpy。不把逐張 ADB 截圖的初步結果外推到持續串流。

**完成條件：** 單一命令可啟動程式與遊戲，連續取得畫面；緩衝區覆蓋行為有可重現測試，擷取間隔、frame 年齡、掉幀與啟動階段都有分布及日誌。遊戲是否進入遊玩狀態仍以畫面確認。

## 2. 虛擬觸控

- 建立可替換的觸控命令與回報介面，包含接觸點 ID、按下／移動／放開、預定時間、呼叫開始與返回、結果及失敗原因。
- 以單一座標變換處理畫面座標到觸控座標的旋轉、裁切、縮放與黑邊；在測試畫面量測映射誤差。
- 分別驗證 Tap、Hold、Move、Flick、兩個以上獨立接觸點，包括同時按下、交錯放開和中途取消。用可見回饋確認各指沒有意外合併。
- 斷線、逾時或停用時釋放仍按住的接觸點。只會單點 tap 的後端須標成能力不足，繼續評估其他後端。

**完成條件：** 在簡單測試畫面中，每種宣稱支援的動作都能被觀察且重現；多指不會意外合併，座標誤差、失敗率與注入耗時有記錄。將後端選型及限制補入架構文件。

## 3. 時間排程與延遲基線

- 用可重現的合成軌跡串接 Observation、Track、HitIntent 與 TouchCommand，保留來源 frame、位置與速度估計、預測時間、信心或不確定度及拒絕原因。
- 使用主機 monotonic clock 實作指定時間的觸控排程；處理過期意圖、重複意圖、同時觸控、取消和衝突。注入開始、返回及畫面首次觀察到效果分別計時。
- 量測預測誤差、排程誤差、注入耗時與擷取間隔在正常和受控負載下的分布，找出尾端尖峰來源。

**完成條件：** 同一組合成軌跡能重現相同決策；過期、取消、衝突及時間誤差有測試。不同批次的量測可重複，並能辨認主要延遲來源與尾端尖峰。

## 4. 簡單目標閉環

- 建立可控制目標出現且能觀察觸控效果的測試畫面；執行時只根據最新 frame 偵測目標，經相同的追蹤、預測、排程與觸控後端自動點擊。
- 對照目標出現真值（只供離線評估）、首次觀察、辨識完成、預定觸控、注入開始／返回及效果首次被畫面觀察到的時間線。
- 在正常與受控負載下重複測試，統計命中、誤點、漏點、端到端延遲與 jitter；確認下游變慢時丟棄舊 frame 和過期意圖。

**完成條件：** 閉環可持續運作，結果可重現，端到端分布及故障案例能解釋。根據此基線決定是否進入遊戲辨識階段，不為展示遊戲操作跳過量測。

## 5. Phigros 介面交接與視覺辨識

- 只根據即時畫面區分選單、載入、遊玩、暫停、結算與未知狀態；每次辨識記錄來源 frame、信心與完成時間。使用者自行登入及選曲，畫面連續通過可設定的遊玩確認條件後程式接手。
- 狀態不明、畫面逾時、ADB 中斷或離開遊玩狀態時，立即清空未送出的命令並釋放接觸點。重新進入遊玩狀態時清空上一局追蹤資料。
- 量測從遊玩畫面首次可辨識到接手的延遲，以及錯誤接手、漏接手、過早停用和停止延遲；測試公告、登入失效、載入、暫停與結算畫面。
- 從簡單、可重複的遊玩片段開始，辨識可見 Note、判定線與相對運動，建立跨 frame 追蹤，估算撞線時間及不確定度。每次預測保留依據的 frame 和軌跡。
- 逐步涵蓋移動／旋轉判定線、遮擋、同時 Note、不同 Note 類型及多指衝突；分別記錄誤辨、漏辨、追蹤切換與預測誤差。只有觸控後端已驗證相應能力，才啟用 Hold / Move / Flick 或多指策略。
- 建立依歌曲與視覺主題切分的標註驗證集；先測可解釋的幾何視覺基線，再以小型偵測／分割模型比較跨譜面泛化及整體尾端延遲。運行中的「記憶」限於近期畫面建立的追蹤與校正狀態，不轉成譜面或固定按鍵回放。

**完成條件：** 可從啟動、使用者自行登入與選曲到遊玩結束完成交接；非遊玩畫面不送出譜面觸控。每次操作或放棄可由畫面、追蹤、預測與觸控時間線解釋，並與第 4 階段基線比較。自動選單導覽不在第一版範圍。

## 6. 整合、回歸與交付

- 在固定環境與不同主機負載下重複完整流程；版本或設定變更後比較 p50 / p95 / p99、最大值、jitter、錯誤接手和觸控失敗率。
- 驗證關閉、遊戲重啟、模擬器斷線與重連、解析度或方向改變、觸控後端失敗時能安全停止，並重新建立正確狀態。
- 更新 README 的安裝、單一命令啟動、使用者自行登入與選曲、故障排查；更新架構文件中的後端選型、資料契約、實測條件與限制。

**完成條件：** 新環境可依文件重現完整流程及量測；已知限制和未支援的 Note／觸控類型明確列出。只有端到端誤差與可比較的判定需求都有數據時，才評估是否達到遊戲操作目標。
