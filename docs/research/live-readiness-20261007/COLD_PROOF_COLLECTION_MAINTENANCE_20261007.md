# Linear read-only cold proof collection

Journal09 completed all fourteen ASan native groups before collecting the previously completed Release and Debug proof. Its read-only collector repeatedly extends a PowerShell array for every file in every prior closure, including duplicates. Array copying grows with the accumulated number of references. This is maintenance bookkeeping, not a measured game/runtime stage.

Journal10 performs no native launch, rebuild, replay, device operation or new test. It verifies all existing journal07 builds, journal09 ASan groups, earlier Release/Debug groups, exact trace comparisons, strict compatibility controls and frozen runtime copies. The original source and expected outcomes remain unchanged. It uses a bounded map of exact path/size/SHA bindings, rejects conflicting bindings, verifies each unique file, and independently rehashes every unique file before writing a fresh aggregate. It does not accumulate an unused list of duplicate input paths. All original root/leaf SHA, before/after receipts, process identities, COMPLETE states and declared historical negative outcomes remain checked.

If the older journal09 driver is stopped, only its identified maintenance PowerShell process may be stopped, after verifying all fourteen native groups are already COMPLETE with no active owned processes. The old partial aggregate directory and all test/build evidence are retained. Journal10 requires every original receipt and does not treat an interrupted driver as completed. The 4 GiB candidate and 32 GiB accumulated capacities remain unchanged.
