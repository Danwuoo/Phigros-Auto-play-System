**Phigros 的 Note 本身**，核心其實只有 **4 種基本類型**：Tap、Drag、Hold、Flick。

| Note | 操作 | 常見用途 |
|---|---|---|
| **Tap** | 到判定線時點一下 | 節奏點、樓梯、縱連 |
| **Drag** | 手指已經壓在判定區即可接住 | 滑軌、長串、視覺引導 |
| **Hold** | 按下並持續按住 | 長音、節奏骨架、多押 |
| **Flick** | 接觸時向任意方向滑動 | 重拍、爆發、滑鍵串 |

其中 Flick 在 Phigros **沒有指定滑動方向**；Drag、Flick 的判定也主要是 Perfect / Miss，而不是要求像 Tap 那樣精確點擊。

但如果是像判定線那樣的 **「Note 可以排成哪些形式／鍵型」**，那就多很多了。

### 單一 Note 排列

最基本可以有：

```text
單點
●

等間隔縱連
●
●
●
●

加速／減速縱連
●
 ●
  ●
   ●
```

再利用 `positionX` 改變 Note 在判定線上的位置，就會形成左右位移。譜面格式本身就是以 Note 的時間、水平位置、速度等資料決定它的出現方式。

所以會有：

```text
樓梯
●
  ●
    ●
      ●

反樓梯
      ●
    ●
  ●
●

折返
●
  ●
    ●
  ●
●

左右交互
●       ●
  ●   ●
●       ●
```

### 多押

同一時間放兩顆以上，就是多押：

```text
雙押

●       ●
─────────
```

也可以：

```text
三押

●   ●   ●
─────────
```

甚至很多顆同時：

```text
● ● ● ● ● ●
───────────
```

Note 類型也可以混合，例如：

```text
Tap + Tap
●       ●

Tap + Flick
●       ◆

Tap + Drag
●       ■

Hold + Tap
┃       ●

Hold + Flick
┃       ◆
```

實際遊玩中，不同種類的重疊／同時 Note 也會形成不同手法。例如 Tap + Flick、Hold + Flick、Flick + Flick、Drag + 其他 Note 都是常見組合。

### Hold 的形式

Hold 特別自由，因為除了起點位置外還有持續時間。

最普通：

```text
│
│
│
●
──────
```

可以做成兩條：

```text
│       │
│       │
●       ●
─────────
```

或者交錯：

```text
│
│   ●
│      ●
●
─────────
```

於是產生：

**Hold + Tap**

```text
│        ●
│     ●
│  ●
●
──────────
```

一隻手 Hold，另一隻手打 Tap。

也可以：

**雙 Hold**

```text
│       │
│       │
│       │
●       ●
─────────
```

甚至：

**Hold 中塞 Flick / Drag / Tap**

```text
│       ◆
│    ●
│  ■
●
─────────
```

這種就很容易形成換手、多指或「一隻手固定另一隻手處理」的配置。

---

### Drag 串

Drag 很適合做「軌跡感」。如果排列足夠緊密，甚至可以把手指放在上面就可以 perfect，他偵測的不是點擊，是她過判定線蒔你的手有沒有在觸控。

```text
■
  ■
    ■
      ■
```

玩家可以用一根手指跟著走。

例如：

```text
Z 字 Drag

■
  ■
    ■
  ■
■
```

或者：

```text
波浪

■
   ■
      ■
   ■
■
   ■
```

如果密度夠高，看起來就像一條黃色軌道。

甚至可以：

```text
兩股 Drag

■             ■
  ■         ■
    ■     ■
      ■ ■
```

形成交叉、合流、分流。

---

### Flick 串

Flick 則常被拿來做爆發感。

```text
◆ ◆ ◆ ◆
```

或者：

```text
◆
  ◆
    ◆
      ◆
```

也可以 Flick 與 Tap 交互：

```text
● ◆ ● ◆ ● ◆
```

因為 Phigros 的 Flick **往任何方向滑都可以**，所以譜面看似向左、向右、斜著飛，並不代表你一定得往那個視覺方向 Flick。

---

### 上下雙面 Note

Phigros 很重要的一種設計是：

```text
    ●
    ↓

──────── 判定線

    ↑
    ●
```

也就是 Note 可以從判定線**兩側**接近。

所以能做：

```text
上 Tap
   ●
   ↓
──────
   ↑
   ◆
下 Flick
```

甚至同時：

```text
●       ●
↓       ↓
─────────
↑       ↑
◆       ◆
```

當判定線再開始旋轉時，「上／下」就只是相對於判定線而言，而不是螢幕真正的上下方向。

這也是 Phigros 很容易產生視覺欺騙的地方。

---

### 交叉／撞擊型

如果配合不同速度，可以讓 Note 視覺上互相穿過：

```text
● →     ← ●
     ×
```

或者從上下兩邊同時撞向判定線：

```text
↓ ●

──────

● ↑
```

再配合判定線移動，就可以造成：

- Note 追判定線
- 判定線追 Note
- Note 看似靜止
- Note 倒退
- Note 突然加速
- 不同 Note 看似互相碰撞

因為每顆 Note 本身都有位置與速度等參數，所以即使實際判定時間很規律，視覺上也能排列得非常不規律。

---

### 常見「鍵型」可以概括成

如果把四種 Note 和排列方式組合起來，大概可以整理成：

**節奏型**

`縱連 / 樓梯 / 交互 / 亂打 / 疊鍵 / 多押`

**移動型**

`直線 / 斜線 / Z 字 / V 字 / X 字 / 波浪 / 螺旋視覺`

**手法型**

`單手縱連 / 左右交互 / 換手 / 多指 / Hold 拘束 / Flick 交互 / Drag 跟手`

**複合型**

`Tap+Tap / Tap+Drag / Tap+Flick / Tap+Hold / Hold+Flick / Hold+Drag / Flick+Drag / 多 Hold`

**空間型**

`單側 / 上下雙側 / 左右 / 四方向 / 多判定線跨線`

社群甚至會把「上下左右四方向都有 Note」的配置稱為類似 **Paradigm 地帶**；V 字判定線配合 Note 下落也有專門的玩家稱呼。

所以如果把 **判定線 + Note** 一起看，Phigros 的基本設計空間其實就是：

**4 種 Note  
× 任意 X 位置  
× 上／下側  
× 不同速度  
× 同時／錯開時間  
× 多判定線  
× 判定線移動／旋轉**

因此能組成的「鍵型」幾乎沒有固定上限。
